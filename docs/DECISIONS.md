# Decisions

Dated decisions with reasons. Newest at the bottom of each day.

## 2026-10-26

- **Python 3.12 venv in `.venv`.** The Mac's default `python3` is 3.14; 3.12 is used for the venv and CI because every dependency we need (numpy, pyserial, PlatformIO) has mature wheels for it. The code still targets Python 3.10+.
- **Pinned dependencies.** `numpy==2.5.4`, `pytest==9.1.1` (the versions that installed and passed the 17 tests on this Mac). Pinned so a later reinstall reproduces the results.
- **PlatformIO in its own venv (`.pio-venv`, git-ignored).** PlatformIO pulls in many packages that the diagnosis code never needs; keeping it separate keeps `requirements.txt` minimal. Version 6.1.18.
- **Provenance on every record.** Each record in `sessions.jsonl` carries `source` (`sim` or `hardware`), `commit` (with `+dirty` when tracked files had uncommitted changes), `policy_hash` (first 12 hex digits of SHA-256 over the sorted policy JSON), `model`, `model_version` (Ollama digest, first 12 hex digits), `seed` and `timestamp` (ISO 8601, Africa/Lagos). Hardware records add `firmware` and `calibration`. Each run directory also has `meta.json`.
- **Records are appended as each trial finishes** (and flushed), so a run that is interrupted or crashes keeps everything up to that point.
- **`summary_table` refuses mixed sources.** It raises if sim and hardware records are passed together, so the two can never end up in one table by accident.
- **Legacy run `results/20261026-102515`** predates the provenance fields. It is a simulation run (no hardware existed). It is left unedited because `results/` is append-only; any loader treats a record with no `source` as `sim` and marks it legacy.
- **Model benchmark settings.** Thinking models (qwen3, qwen3.5) are benchmarked with reasoning switched off (`reasoning_effort: "none"` on Ollama, `enable_thinking: false` on llama.cpp). Measured on this Mac with the same first hybrid prompt: qwen3:8b took 26.7 s per call with thinking on (about 460 generated tokens) and 1.3 s with it off. At 10 to 20 calls per session and 340 LLM sessions in Phase 2, thinking on is not workable. `--think` keeps it available.
- **A model timeout counts as an invalid call and the hybrid falls back to the engine at once** (no retry: a retry would wait the full timeout again). A server that is down or refuses the request (`LLMUnavailable`) stops the whole run instead of producing a column of crashed trials.
- **Final held-out faults frozen on 26 Oct 2026** (working rule 6). H1 and H2 are now "development held-out". The final set, in `faultdiag/heldout.py`:
  - H3, element `main_wiring`: resistance between the battery terminal and the bus (corroded fuse holder or main wiring), 0.3 to 0.6 ohm against a healthy 0.01 ohm.
  - H4, element `current_sensor_src`: failing INA226 on the battery output channel, reading low with a gain of 0.45 to 0.65 (as after a calibration-register reset or a damaged shunt joint). It affects `read_current src` and the source current fields of both load tests.
  Both use elements already in the answer vocabulary, so no method gets a hint from new element names. They form the test set `heldout_final`, appended after TF2 so every earlier scenario keeps its seeds. `run_all` and `run_experiment.py` refuse them unless `--final` is given. Only bench-physics tests touch them before the final run; no method has been run on them, and no prompt or threshold has been tuned against them.
- **`FaultState.current_gain`** (new, default empty) carries a current-sensor gain error. Only the held-out module sets it; the engine's fault atoms never do, so the engine's model is unchanged.
- **Phase 3 transport: pyserial 3.5** (pinned in `requirements.txt`). It is the standard serial library for Python on macOS, Linux and Windows and has no dependencies of its own. It is imported only inside `SerialLink`, so simulation-only use does not need it.
- **Serial design.** One reader thread routes responses by id and handles events; one heartbeat thread sends a heartbeat each second when nothing else was sent, so a model that thinks for a minute does not trip the firmware's 3 s host-heartbeat cutoff. Timeouts come from `policy.json` (`timeouts_s.default` for readings; a load test adds its on-time; `timeouts_s.human_probe` for the technician). A late, duplicate or unknown response id is logged and dropped. A `hello` after connecting means the board reset: the session is marked interrupted and `BenchInterrupted` is raised on the next call.
- **The host waits out the firmware's thermal cool-down** (up to 30 s) instead of reporting a refused load test as a failed measurement. The firmware still enforces the limit; the host only avoids wasting the method's call.
- **Mock devices** (`faultdiag/mockdevice.py`) speak both firmware protocols with readings from the simulator, so the transport, the injector driver, calibration, the self-test script and the whole hardware runner are tested without a board, including over a real pseudo-terminal through pyserial. Anything run on them is labelled `sim` and saved under `results/mock-serial/`. The mock's cool-down can be shortened (`cooldown_scale`) for quick pipeline checks; the real firmware's cannot.
- **Hardware sessions are blind.** `run_hardware.py` writes session records without scenario or truth; the truth goes to `truth.jsonl` in the same run directory, which no method reads, and `grade()` joins the two only after the run ends. Blocks (scenario, trial) run in a random order; within a block every method runs on the same injected fault, in random order, so the comparison is paired.
- **Tool failures on hardware are injected in the host** (`ToolFailures`, between the policy guard and the bench), because the bench cannot be made to time out or return garbage on demand. Recorded in the truth file.
- **F1b is not run on hardware.** One series resistor (0.22 ohm) gives one severity, inside the simulator's "degraded" range.
- **Calibration** is a straight line per channel (reported = raw x gain + offset), fitted at three supply voltages (6, 10, 13 V) against the handheld meter. Records are dated files in `calibration/`, never overwritten. A hardware run refuses a board whose calibration id is not the latest record, or a record older than 30 days, unless `--allow-stale-calibration` is given. The firmware refuses gains outside 0.5 to 2 and offsets outside -2 to 2.
- **Noise refit rule** (`scripts/refit_noise.py`): simulator noise = median sample standard deviation of repeated raw readings, scaled by the gain; engine sigma = 3 x root-sum-square of that noise and the calibration fit residual (the same 3:1 margin as today's 0.03 V against 0.01 V). Before: `noise_v 0.01`, `noise_i 0.005`, `sigma_v 0.03`, `sigma_i 0.02`. After: **not yet run**, no calibration data exists. The script only proposes; applying it changes every simulated result, so it is a recorded decision, not an automatic step.
- **Test-load switch on the high side** (P-MOSFET with an NPN driver). The model returns the test load through the shared return (`ret`); a low-side switch with its source on `ret` would lose gate drive when H1 lifts `ret` by several volts.
- **Injector relay 1 moved from GPIO 14 to GPIO 27**: GPIO 14 toggles during ESP32 boot and would click a fault relay.
